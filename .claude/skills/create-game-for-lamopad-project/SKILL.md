# Как делать игры для lamopad.ru — общие требования ко всем играм

Эталонная реализация: /tracks/sun-coming-glasses/game/ («Солнценаступательные очки»).
Когда делаешь новую игру — сверяйся с ней.

## Суть

- Игра делается ПОД ТРЕК: дизайн, визуальные образы и МЕХАНИКИ должны
  вырастать из вайба, текста и обложки конкретного трека. Не «игра + песня»,
  а игра, которая была бы невозможна с другим треком.
- Игра должна соответствовать концепции артиста Ламопад: странник/искатель,
  радостный абсурд + глубокая тоска, дорога, ламы, красный рюкзак, побег из
  рутины, экзистенциализм, отсылки, русская культура, но в далёком экзотическом путешествии. Никакой чужой эстетики.
- Трек играет фоном: стриминг через <audio>, разлочка первым жестом,
  РАЗДЕЛЬНЫЙ мут музыки и SFX (две кнопки в игре + тумблеры на старте),
  состояние в localStorage (ключи lamopad_<игра>_*).

## Обязательные экраны

### Экран загрузки
- Заголовок игры с переносом длинных слов (не растягивать по горизонтали).
- Анимированный персонаж/символ игры.
- Внизу скромно: «ламопад» (ссылка на главную) и под ним мелко
  «© кое-какие права защищены» (10px, opacity ~0.55).
- Без хаверов — экран мимолётный.

### Стартовый экран (полноценная сцена, НЕ модалка с формой)
- В стиле игры: фон, декор, анимации из мира игры (CSS, без внешних ресурсов).
- Заголовок с вайбом трека. Подходящий по смыслу Hover.
- Тумблеры-пилюли (✓/✕): «музыка», «звуки», «весь экран» (текстом, не значком;
  прятать, если Fullscreen API нет — iPhone).
- Заметное предупреждение: «В ИГРЕ ЕСТЬ МУЗЫКА И ЗВУКИ».
- CTA-кнопка с большим «гало-солнцем» (вращающиеся лучи + дышащее ядро).
- Переход в игру — анимированный, в стиле игры (у очков: прыжок + экран
  уносится вверх). Пока стартовый экран открыт — игра не реагирует на ввод.
- «ламопад» + копирайт внизу (как на загрузке), кнопка «другие игры» → /games/.
- Если ориентация горизонтальная — подсказка «рекомендуем вертикально».
- Тематические хаверы на всём (заголовок вспыхивает, персонаж ловит блик...).

### Экран смерти/финала (нативный, без панели-коробки)
- Фирменная цитата + причина смерти + результат (крупно, градиентом) + рекорд.
- CTA: сыграть ещё раз (брендовый текст, свечение go-glow).
- Вторичный CTA: «🎧 добавить трек к себе» → экран благодарности:
  «Спасибо! Рад, что трек понравился» + большие ссылки-пилюли с брендовыми
  цветами и глоу-хаверами: Яндекс Музыка, VK Музыка, Spotify, Apple Music,
  Звук, YouTube · клип, ⬇ Скачать mp3. Ссылки брать со страницы трека.
- «🎮 ХОЧУ ИГРУ ПОД СВОЙ ТРЕК» (капсом, чуть крупнее) → экран заказа.
  Экран заказа НЕ хардкодить: общий модуль /lib/order-widget.js, все тексты
  и контакты (описание, почта с копированием, телеграм, «а какие ещё игры
  у тебя есть?» → /games/) живут в LAMOPAD_ORDER — правятся один раз на весь
  сайт. Простой путь: LamopadOrder.open({тема под стиль игры}); если своя
  разметка — LamopadOrder.fill(...) + LamopadOrder.bindMailCopy(почта).
  Все опции и примеры — в шапке самого модуля.
- В том же едва заметном ряду — «🔗 поделиться»: navigator.share (если есть)
  или копирование в буфер (текст + ссылка на игру, кнопка на 1.8с меняет
  подпись на «✅ скопировано!»). Если в игре есть рекорды — делимся
  рекордом («Я НАПРЫГАЛ X МЕТРОВ» — брать именно best, а не результат
  текущего забега). Если рекордов нет — делимся просто ссылкой на игру
  с фразой в духе трека.
- Ниже отдельным рядом едва заметное: «другие игры» → /games/.

## Геймплей

- МИКРО-ТУТОРИАЛ всегда: игрок должен понять управление за первые секунды
  без текста-простыни (пример: офисное вступление + «Тапни — и к чёрту
  потолок!» + первые лёгкие платформы).
- Постепенная сложность: одна новая механика за раз, «лесенкой».
- Процедурная генерация — с анти-блокерами: уровень ВСЕГДА проходим
  (проверять досягаемость по физике, запрещать смертельные комбинации).
- Смерть — с причиной, рекорды в localStorage.
- Чит-коды для тестирования каждой фичи (набор слова с клавиатуры): копим
  нажатия в буфер (последние ~8 символов), на каждый keydown проверяем
  `buf.endsWith('слово')`, сработавший код сбрасывает буфер.
- Пасхалки и абсурдный юмор приветствуются.

## Технически
- Mobile-friendly.
- Мобилка + комп одинаково важны: тач-зоны, клавиатура, wrap/отзывчивость.
- Phaser 3 из общего /lib/phaser.min.js (скачан локально — CDN нестабилен
  в РФ). Относительный путь, нижний регистр, как и ВСЕ пути.
- ES-модули без сборки. Разделение на модули: config.js (ВСЕ константы),
  main.js (DOM/аудио/оверлеи), scenes/ (boot/game/ui), objects/ (сущности).
  DRY, reusable, читаемый код; комментарии по-русски, по делу.
- Поле подгонять под вьюпорт НА МОМЕНТ ЗАГРУЗКИ (innerWidth/innerHeight,
  нормировать к портрету, клампить) — иначе FIT оставляет поля по бокам;
  панели мобильного браузера не прячутся, экран (screen.*) не годится.
- Канвас защитить: touch-action: none, user-select: none,
  -webkit-touch-callout: none.
- Тач-устройство = лоу-графика (меньше частиц, реже эффекты).
- Текстуры рисовать процедурно в boot-сцене (canvas), без бинарных ассетов,
  где возможно.
- SEO-optimized: title, description, h1, keywords, og-теги, canonical.
- Аналитика — сниппет GoatCounter в <head> (единый для всего сайта):
  <script data-goatcounter="https://lamopad.goatcounter.com/count"
          async src="//gc.zgo.at/count.js"></script>

## Банальные оптимизации — сразу, не потом

- Phaser Text НЕ перерисовывать каждый кадр: HUD-числа троттлить
  (~45мс комп / ~90мс тач), setText только при изменении.
- Всё, что ушло за камеру навсегда, — удалять (свип раз в секунду).
- Пулы спрайтов для массовых объектов; при возврате в пул ОБЯЗАТЕЛЬНО
  scene.tweens.killTweensOf(sprite) — иначе «невидимые платформы».
- ADD-blend частицы — умеренно (рвут батчинг WebGL).
- px/сек × delta с клампом dt (~0.05с) — защита от возврата на вкладку.
- Тяжёлые пулы частиц/эффектов, нужные только с определённой высоты/этапа
  (дождь, метель и т.п.) — создавать ЛЕНИВО (по приближению к этой высоте
  с запасом), а не в create() сцены. Иначе они простаивают и платят за
  проверку рендера каждый кадр всю раннюю игру, где не нужны.

## Debug-оверлей (?debug=true)

Обязательно: js/debug.js — маленький модуль, включаемый параметром `?debug=true`
в URL. Эталон — /tracks/sun-coming-glasses/game/js/debug.js, копировать как есть:
- `Debug.init()` — один раз в main.js, до создания `new Phaser.Game(...)`.
- `Debug.mount(scene)` — один раз в сцене, которая всегда на экране (обычно UI-сцена).
- `Debug.update(time)` — каждый кадр из update() той же сцены.
- `Debug.set('ключ', значение)` — откуда угодно в игре, сколько угодно часто
  (сама перерисовка троттлится изнутри — вызовы ничего не тормозят).
Показывает FPS всегда, плюс любые `Debug.set` значения — обычно стоит завести:
состояние (`this.state`), высоту (текущую/максимум), число активных платформ/
объектов пула, скорость игрока, таймеры активных механик (джетпак/пузырь/
что там ещё есть в конкретной игре). Это единственный способ на живую посмотреть,
что происходит внутри игры на телефоне, где консоли нет — не пропускать.

## После создания игры

- Добавить страницу в sitemap.xml.
- Добавить карточку игры в /games/, следуя дизайну раздела.
- Завести sounds/ozvuchka.md — список всего, что нужно озвучить,
  с чекбоксами и контекстом.
